01.한전 연구직 채용에 지원하게 된 동기837 / 1000자

[전력 도메인과 AI 학습 데이터, 두 경험이 만나는 자리]

약 3년간 민간 가상발전소(VPP) 플랫폼과 전력거래소 기준서 기반 고객기준부하(CBL) 계산 시스템을 개발·운영하며 전력 데이터를 다뤘습니다. 이후에는 단기 계약으로 AI 학습 데이터 구축 사업에 참여해 전문 분야 텍스트 데이터의 품질 검수를 맡았고, 현재는 차세대그리드 연구소에서 전력망 연구 플랫폼의 웹 운영과 소프트웨어 유지보수를 담당하고 있습니다.

AI 데이터 구축 현장에서 배운 것은 분명했습니다. 입법례와 정책 문서를 학습 데이터로 가공하는 과정에서, 검수자마다 판단 기준이 달라지면 데이터 품질이 그대로 흔들린다는 점을 확인했습니다. 기준을 문서로 통일하고 자동 검증 규칙을 만들어 걸러내자 검수자들은 비로소 맥락 판단에만 집중할 수 있었습니다. 모델의 성능은 결국 학습 데이터의 일관성에서 갈린다는 것을 실무로 배운 시기였습니다.

전력 산업에 특화된 언어 모델과 AI 솔루션을 만들려면, 전력 도메인의 문서와 데이터를 읽어낼 수 있는 사람이 데이터를 다듬어야 한다고 생각합니다. 전력거래소 기준서를 조문 단위로 해석해 알고리즘으로 옮겨 본 경험과, 대규모 학습 데이터의 품질을 기준부터 세워 관리해 본 경험이 만나는 지점이 이 직무라고 판단했습니다.

무엇보다 전력 특화 AI는 계통·설비·수요 데이터를 실제로 보유한 곳에서만 만들 수 있습니다. 그동안 계약 단위로 짧게 참여하며 도메인 지식이 충분히 축적되기 전에 프로젝트가 끝나는 아쉬움이 컸습니다. 데이터가 있는 자리에 오래 머무르며, 모델이 학습할 수 있는 형태로 데이터를 만들고 그 결과를 현업이 쓸 수 있는 플랫폼까지 연결하는 일을 하고자 지원했습니다.

02.지원직무와 관련된 지식 및 보유 Skill, 연구실적, 경력, 경험 등 (사용 Tool 포함)1757 / 2000자

[AI 학습 데이터 구축 및 품질 관리] 국회 입법 분야 AI 학습 데이터 구축 사업에서 외국 입법례·정책 등 전문 텍스트의 최종 품질 검수를 담당했습니다. 검수자 간 기준 편차를 없애기 위해 검수 표준 가이드와 업무 FAQ를 문서로 정착시켰고, 수작업 대조의 한계를 넘기 위해 검수 웹 플랫폼을 직접 개발했습니다. 중복 데이터 필터링, JSON 포맷 검사, 필드 간 논리 모순 확인 등 10가지 자동 검증 규칙과 대용량 ZIP 일괄 처리, 실시간 품질 통계 화면을 구현해(React, TypeScript, FastAPI, Supabase, Docker) 검수자가 단순 오류 확인 대신 문맥 검증에 집중하도록 만들었습니다.

[전력 도메인 데이터 처리] 전력거래소 기준서에 명시된 CBL 알고리즘 7종(MAX_4_5, MID_4_6, JP_STANDARD_BL 등)을 한국·일본 전력시장 규정에 맞춰 Python으로 구현하고, 수요반응 성과 검증 지표(RRMSE)를 산출했습니다. 15분·30분·60분 주기의 대용량 시계열 전력 데이터는 KDB+ 시계열 데이터베이스의 Q 언어로 조회·가공했으며, 이상치를 분석해 계산 결과의 정확도를 관리했습니다. 전력 데이터의 구조와 규정 언어를 함께 다뤄 본 경험입니다.

[빅데이터 플랫폼 구축] 분산 에너지 자원의 시계열 데이터를 분석·시각화하는 플랫폼을 기획 단계부터 구축했습니다. CSV, VPP API, AWS S3 등 여러 소스에서 1분 주기로 데이터를 수집하는 파이프라인을 만들고, PostgreSQL 스키마 설계와 30여 개 REST API 개발, 다중 시리즈 차트와 드래그앤드롭 대시보드 구성까지 담당해 실무자가 필요한 통계를 직접 조합하도록 했습니다.

[AI 활용 서비스 개발] 개인 프로젝트로 대규모 언어 모델(Google Gemini) API를 연동한 링크 관리 서비스를 개발해 운영 중입니다. 수집한 문서를 자동으로 카테고리 분류·한국어 요약·태그 추출하도록 구성했고, API 호출의 Rate Limiting 대응과 기존 데이터 벌크 백필 처리의 안정성을 확보했습니다. Next.js와 Supabase 기반으로 구축하고 46개 테스트로 품질을 검증하고 있습니다.

[데이터 분석 및 성능 개선] Pandas와 Scikit-learn(K-Means, DBSCAN)으로 고객 부하 패턴을 군집화했고, 선형 프로그래밍(PuLP/Pyomo)으로 ESS 충·방전 스케줄링 최적화 모델을 작성했습니다. 동기식 Flask API의 블로킹 문제를 진단해 Uvicorn ASGI 기반 FastAPI로 전환하고 Gevent 분산 태스크 워커를 배치해, 오래 걸리는 연산이 전체 요청을 막지 않는 구조로 개선했습니다.

[현재 수행 업무] 차세대그리드 연구소에서 연구 플랫폼의 웹 운영과 소프트웨어 유지보수를 맡아, 연구진이 다루는 전력망 데이터가 정확히 표시되도록 인터페이스를 개선하고 플랫폼 인프라를 구축·관리하고 있습니다.

[보유 Skill 및 사용 Tool] 언어·백엔드: Python(FastAPI, Flask), Spring Boot, TypeScript / 데이터·분석: PostgreSQL, KDB+, Pandas, Scikit-learn, PuLP, Pyomo / AI: Google Gemini API 연동, 학습 데이터 품질 검증 자동화 / 프론트엔드: React, Next.js, Vue.js, Highcharts / 인프라: Docker, GitHub Actions CI/CD, AWS(EC2, Elastic Beanstalk, S3, Lightsail), Vercel.

03.입사 후 목표686 / 1000자

[전력 데이터를 AI가 학습할 수 있는 자산으로]

입사 후 1년은 한전이 보유한 데이터의 구조와 업무 규칙을 파악하는 데 집중하겠습니다. 어떤 데이터가 어디서 생성되고 어떤 규정에 따라 해석되는지를 현업 담당자에게 물어 가며 익히겠습니다. 전력거래소 기준서를 조문 단위로 읽어 코드로 옮겼던 방식 그대로, 도메인 언어를 먼저 이해한 뒤 손을 대는 순서를 지키겠습니다.

이어서 전력 도메인 데이터를 모델이 학습할 수 있는 형태로 만드는 일을 맡고 싶습니다. 전력 산업 특화 언어 모델의 성능은 설비 이력, 규정 문서, 계통 운영 기록이 얼마나 일관된 기준으로 정제되어 있는가에 달려 있다고 생각합니다. 학습 데이터의 품질 기준을 세우고 자동 검증 체계를 만들어 사람이 판단해야 할 부분에만 집중하도록 하는 일은, AI 데이터 구축 현장에서 제가 직접 해 본 일입니다.

중장기적으로는 만들어진 모델이 현업에 닿는 마지막 구간을 책임지고 싶습니다. 아무리 좋은 모델도 담당자가 묻고 확인할 수 있는 화면이 없으면 업무로 이어지지 않습니다. 데이터 수집·정제·학습·활용이 하나의 플랫폼에서 순환하도록 만들고, 현장 부서가 별도 요청 없이 직접 활용하는 AI 환경을 구축하는 것이 목표입니다.

전력 도메인을 읽을 수 있고, 학습 데이터의 품질을 관리해 봤으며, 그 결과를 서비스로 만들어 본 경험을 모두 갖춘 인력이 되겠습니다.
